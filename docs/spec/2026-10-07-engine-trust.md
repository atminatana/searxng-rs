# ТЗ 2026-10-07-engine-trust: снижение блокировок со стороны поисковиков

- **Статус:** утверждено владельцем 2026-10-07 («утверждаю, по рекомендациям»: Р1(а), Р2(а), Р3(а), Р4(а))
- **Постановка владельца:** «сделай пункты 1-5» из оценки «как повысить доверие
  поисковых движков к инструменту» (2026-10-07)

## Цель

Уменьшить число блокировок (HTTP 403/429, капча, тайм-ауты) со стороны
поисковиков за счёт снижения нагрузки на них и более правдоподобного HTTP-клиента.
Внешний контракт MCP, JSON API и CLI не меняется, кроме новых текстов ошибок.

## Границы

**Входит:**

1. Приостановка движка после ошибок (порт `SuspendedStatus` из SearXNG).
2. Кэш результатов движков на короткое время.
3. Ограничение частоты запросов к каждому движку.
4. Сохранение cookie между запросами (общий cookie jar HTTP-клиента).
5. Согласованные браузерные заголовки и актуальный User-Agent.

**Не входит:** официальные API (пункт 6), подмена TLS/HTTP2-отпечатка
(SearXNG делает её через curl_cffi), ротация IP/прокси, лимиты входящих запросов.

## Контракты

### 1. Приостановка движка (эталон: `searx/search/processors/abstract.py`, `online.py`, `settings.yml`)

Состояние на движок, общее для всех MCP-сессий и запросов API:
`continuous_errors`, `suspend_end_time`, `suspend_reason`.

| Ошибка движка (`EngineError`) | Пауза, с | Ключ конфига `[search.suspended_times]` |
|---|---|---|
| `AccessDenied` (402/403) | 180 | `access_denied` |
| `Captcha` | 3600 | `captcha` |
| `TooManyRequests` (429) | 180 | `too_many_requests` |
| `CloudflareCaptcha` | 1296000 | `cf_captcha` |
| `Timeout`, `Request`, `Http(5xx и прочие)` | `min(max_ban_time_on_fail, ban_time_on_fail)` = 5 | `[search] ban_time_on_fail`, `max_ban_time_on_fail` (уже есть) |
| `Parse`, `NoResults` | не приостанавливает | — |

- Пауза 0 отключает приостановку для этого типа ошибки.
- Успешный ответ сбрасывает состояние.
- Приостановленный движок не опрашивается; его исход — `EngineError::Suspended`
  с причиной и оставшимся временем; клиент MCP видит это в
  `engine errors: <engine>: engine suspended (...)`.

### 2. Кэш результатов (в эталоне нет — отступление, ADR)

- Кэшируются только успешные исходы одного движка.
- Ключ: движок, текст запроса, язык, safesearch, страница, категория.
- `[search] cache_ttl` — секунды, по умолчанию 300; 0 отключает кэш.
- `[search] cache_max_entries` — по умолчанию 1000; при переполнении удаляются
  самые старые записи.

### 3. Частота запросов к движку (в эталоне нет — отступление, ADR)

- `[search] engine_min_interval` — минимальный интервал между запросами к одному
  движку, секунды, по умолчанию 1.0; 0 отключает.
- Поведение при превышении — см. открытое решение Р3.

### 4. Cookie

- Один cookie jar на HTTP-клиент; cookie, выставленные сайтом, отправляются ему в
  следующих запросах. Эталон: клиенты httpx в SearXNG хранят cookie между запросами.
- Явные cookie движков (brave, yandex, yahoo, startpage) продолжают работать.

### 5. Заголовки и User-Agent

- К каждому запросу добавляются заголовки навигации Firefox: `Accept`,
  `Accept-Language` (как сейчас), `Upgrade-Insecure-Requests: 1`,
  `Sec-Fetch-Dest: document`, `Sec-Fetch-Mode: navigate`, `Sec-Fetch-Site: none`,
  `Sec-Fetch-User: ?1`.
- User-Agent по умолчанию — см. открытое решение Р1. `[outgoing] user_agent`
  в конфиге по-прежнему переопределяет значение.

## Открытые решения (нужен выбор владельца)

- **Р1. User-Agent.**
  (а) актуальный Firefox без приписки `searxng-rs/0.1`, как `gen_useragent()`
  в SearXNG — *рекомендую*;
  (б) оставить приписку: честнее, но клиент проще распознать и заблокировать.
- **Р2. Кэш.** (а) кэш исходов отдельных движков, 300 с — *рекомендую*: разные
  наборы движков переиспользуют одни записи; (б) кэш целого ответа поиска.
- **Р3. Превышение частоты.** (а) ждать свободного слота в пределах тайм-аута
  запроса, иначе ошибка `rate limited` — *рекомендую*; (б) сразу пропускать
  движок с ошибкой `rate limited`.
- **Р4. Значения приостановки.** (а) как в SearXNG (таблица выше) —
  *рекомендую*; (б) свои значения.

## Критерии приёмки

1. После `Captcha`, `AccessDenied`, `TooManyRequests`, тайм-аута движок
   не опрашивается указанное время; клиент получает причину `engine suspended`.
2. Успешный ответ сбрасывает счётчик ошибок движка.
3. Повторный одинаковый запрос в пределах `cache_ttl` не делает HTTP-запроса
   к движку и возвращает те же результаты; ошибки не кэшируются.
4. Два запроса к одному движку подряд разделены не менее чем
   `engine_min_interval`.
5. Cookie, выставленная сайтом в ответе, уходит ему в следующем запросе.
6. Запрос несёт заголовки из п. 5 и User-Agent по решению Р1.
7. Значения 0 отключают соответствующий механизм.
8. Все проверки 1–7 покрыты офлайн-тестами (без сети); `cargo build`,
   `cargo clippy --all-targets` без предупреждений, все тесты зелёные.
9. Живая проверка через MCP: bing и duckduckgo отдают результаты.
10. ADR для отступлений от эталона (кэш, ограничение частоты); описание
    в `PROJECT_MAP.md`.
